# Cómo contribuir

Gracias por tu interés en este proyecto.  
Thank you for your interest in this project.

## Principios básicos / Basic principles

1. **Claridad primero.** Cualquier contribución debe ser entendible por una persona no técnica.
2. **Atribución obligatoria.** Dale crédito al proyecto original y autor.
3. **Comparte los cambios importantes.** Si modificas supuestos, rúbricas, métricas o hallazgos, idealmente notifica al autor original y libera tus aportes bajo la misma licencia (CC BY-SA 4.0).
4. **Honestidad sobre limitaciones.** Documenta debidamente dudas, sesgos y límites de lo que propones.

## Formas de contribuir / Ways to contribute

- Correr pruebas reales con los prompts existentes y compartir los resultados anotados (respetando el formato de `results/`).
- Proponer mejoras a las rúbricas o a los prompts (como issues o pull requests).
- Añadir nuevas personas / escenarios que respeten el Threat Model.
- Mejorar el marco de métricas y las visualizaciones.
- Traducir o mejorar la claridad de la documentación.
- Señalar sesgos o puntos ciegos del marco actual (Ayurveda + Testing + lenguaje DSM-5).

## Proceso sugerido / Suggested process

1. Abre un issue describiendo lo que quieres hacer o el problema que encontraste.
2. Si vas a modificar código o documentos sustanciales, crea un fork y un pull request.
3. En el pull request explica:
   - Qué cambia
   - Por qué
   - Cómo se relaciona con los riesgos de agencia, regulación del sistema nervioso o antropomorfización
4. Mantén el lenguaje simple y accesible.

## Licencia de las contribuciones

Al contribuir aceptas que tus aportes se liberen bajo la misma licencia del proyecto (CC BY-SA 4.0 + el aviso adicional de atribución y notificación).

## Contacto / Contact

Cuando el repositorio sea público, usa issues o el canal que se indique en el README.  
Hasta entonces, cualquier mejora o hallazgo importante se agradece que se comparta con el autor original.

# How to contribute

Thank you for your interest in this project.

## Basic principles

1. **Clarity first.** Any contribution must be understandable to a non-technical person.
2. **Mandatory attribution.** Give credit to the original project and author.
3. **Share significant changes.** If you modify assumptions, rubrics, metrics, or findings, ideally notify the original author and release your contributions under the same license (CC BY-SA 4.0).
4. **Honesty regarding limitations.** Properly document uncertainties, biases, and the limitations of your proposal.

## Ways to contribute

- Run real tests using existing prompts and share annotated results (following the `results/` format).
- Propose improvements to rubrics or prompts (via issues or pull requests).
- Add new personas or scenarios that align with the Threat Model.
- Improve the metrics framework and visualizations.
- Translate or improve the clarity of the documentation.
- Point out biases or blind spots in the current framework (Ayurveda + Testing + DSM-5 language).

## Suggested process

1. Open an issue describing what you want to do or the problem you encountered.
2. If you plan to modify code or substantial documents, create a fork and submit a pull request.
3. In the pull request, explain:
- What is changing
- Why
- How it relates to agency risks, nervous system regulation, or anthropomorphization
4. Keep the language simple and accessible.

## Contribution license

By contributing, you agree to have your contributions released under the same license as the project (CC BY-SA 4.0 + the additional attribution and notification notice).

## Contact

Once the repository is public, please use issues or the channel specified in the README. In the meantime, any improvements or significant findings are appreciated if shared with the original author.
